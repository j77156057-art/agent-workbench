## E. 「不必X，只要X」判 granted —— **我误判了，已撤回**（`569d7fb`）

**结论先说：`granted` 是对的，这一族没有缺陷。**

我曾把它记成**安全方向缺陷**（「用户明说『不必重构』，护栏却放行」）。
**那是误读语义。**

`不必重构，只要重构一下` = 「不用大改，小改一下就行」—— 这是**正当的范围限定请求**，
与 `不要改 README，改一下代码` 完全同一形状。后半句出现写动词不是「否定漏掉了」，
是**用户重新授权了一次**，只是范围更小。

### 逐句实测（5/6 granted，全部正确）

| 句子 | 判定 | 是否正确 |
|---|---|---|
| 不要改 README，改一下代码 | granted | ✓ 正当范围限定 |
| 别动 b.py，a.py 改一下 | granted | ✓ |
| 不必重构，只要重构一下。 | granted | ✓ |
| 不必修复，只要修复它。 | granted | ✓ |
| 不必动配置，把 a.py 改一下 | granted | ✓ |
| 不要动这个文件，改那个文件 | **denied** | ✗ **过拦** |

### 真正在这一族里出问题的是**反方向**

`不要动这个文件，改那个文件` 被 denied —— 差的是第二句用了**裸「改」**，
而裸动词刻意不进表（加了会误伤 `分析一下写操作和读操作的区别` 那 5 句名词用法）。
所以：

```
不要动这个文件，改一下那个文件   granted   ← 「改一下」在词表
不要改 a.txt，改 b.txt          denied    ← 裸「改」不在词表
```

**差两个字，判定相反。** 这是 B 节（谓语动词缺口，`bf19098`）的**残余**，不是新缺陷。

守卫：`tests/test_write_lease_wiring.py::test_the_scoped_negation_shape_is_granted_and_that_is_correct`
与 `::test_the_scoped_negation_with_a_bare_verb_is_still_blocked`。

### 我栽的那一次，以及教训

更糟的是我留了一条**把误读当事实钉住**的守卫：

```python
assert _write_intent("不必重构，只要重构一下。") == G, (
    "...这一族被修了，请把这条记录改成断言它应当 denied 的形式")
```

**它在保护一个错误结论** —— 谁要是把这一族「修」成 denied，这条会红，
而那个「修复」是错的。

那一晚我三次因为「不验就下结论」出错：断言了没测过的系统状态（「上下文满了」）、
拿数量相等当逐项相等（6 处 capability 漂移）、**这次**（拿自己的第一反应当语义）。
第 3 次的教训最具体：**我给自己造的语料标了「期望」，然后就信了自己的标注** ——
那 3 句的「期望=拒绝」是我凭直觉写的，而直觉是错的。

**别信自己标的期望值，先逐句问「这句到底授权没授权」。**

## F. 写租约的三条约束（`73404af` 已修）

### F1 租约不能把 agent 锁在「能写但不能读」

`_lease_blocked` 的语义是**收窄**。只含 `write_*` 的租约会把 `read_file` 一起拦掉，
agent 连要改的文件都读不到。**比原缺陷更糟。**

铸出后必须一并授予 `read_local` / `read_external`，但**不加** ADMIN/EXEC/NETWORK。

### F2 判空必须在补只读**之前**

补完只读再判空，`selected` 永远非空，于是一份「只含只读」的租约会顶着写租约的
名字被铸出来。

### F3 TTL 是「本轮批准过」，不是长期授权

默认 300s、硬上限 900s、下界 1s。放长意味着一句「改吧」之后整个会话都能写。

守卫：`tests/test_write_lease.py`

| 护栏判定 | 有效租约 | 结果 |
|---|---|---|

## J1. 不做「录放机制」（http-recorder 思路，已证不适用）

曾考虑：为跨轮批准失效造一套「录下用户请求/模型响应，之后重放」的机制。
**结论：已证不适用。** 写在这里是为了免得下一个人看到「测试在说谎」又去建它。

**为什么不适用：**

1. **要录的东西在本地运行时并不稳定。** 探针一旦脱离 pytest 就会看见缓存
   （那天栽的第 8 次探针 bug），录下来的东西**复现不了**。
2. **它绕过的是「机制」而不是绕过症状。** 跨轮批准失效的根因是**词表逐条消息判定**：
   用户第 1 轮说「改一下」，第 2 轮只说「继续」，第 2 轮的消息里**没有**批准词，
   所以判定必然退回 `uncertain`。录放只是让第 2 轮「看起来」像有批准词，
   而那与机制的真实状态无关。
3. **结构化授权已经存在，不需要录。** `_lease_blocked`（活）+ `capability_lease`
   （当时死）就是这条路的正解：**granted 轮次铸租约，后续轮次读租约**。
   租约是结构化的、可测的、能进守卫的；录放片段不是。

**替代方案已落地**：`773deaf` 铸租约、`449ebf9` 接上判定与优先级。

**四条规则**：

1. **先怀疑探针再怀疑被测物。**
2. **单个读数不足以定性。**
3. **变异与回归一律打全部相关文件** —— 只跑新文件会全绿并提交，冲突在组合跑时才
   暴露（今天印证三次；第 4 条那次是**全量回归**抓到的）。
4. **探针算的东西必须和被测对象逐字一致**（第 9 次）。自己拼一个「应该长这样」的
   输入去问判定函数，量到的不是那个函数的输入。
5. **守卫要挂在机制上，不是环境上**（第 10 次）。用 `tmp_path` 造夹具，别依赖仓库布局 ——
   仓库里有没有某个文件是布局问题，与这条守卫要验的东西无关。

**第 9 次与前面八次不同**：前八次是「量错了东西」，数据本身就错。
第 9 次**数据是对的但我读错了** —— 我重建的输入算出了 `denied`，而真实路径是
`granted`。教训是**别信自己拼出来的输入**，要么从被测对象里取，要么做决定性实验
（临时换回旧逻辑跑一遍：13 passed vs 2 failed 一次就定性了）。

还有一次不是探针 bug 但同族：**误读语义**（E 节）。量对了、代码形状也看了，
但把「否定 A、授权 B」当成了「用户说不必，护栏却放行」。**自己标的「期望值」不能信。**
