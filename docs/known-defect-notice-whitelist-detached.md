# 已知缺陷：notice 过滤白名单与后端脱钩，运行期提示在任务结束后仍显示

> **归属：前端**（`frontend/src/workbench/composables/useChatStream.ts`）。
> 后端侧可能需要给事件加结构化标记。
> **发现于** 2026-10-10，用户截图：「任务已完成 · 40s」但横幅仍写
> 「模型输出尚未结束，正在继续执行。」
>
> **docs/ 与 tests/ 里都没有记过这条** —— 是空白，不是既有结论。
> 下方每条断言均实测（方法见 §6）。

## 1. 现象

任务已经跑完、卡片显示「已完成 · 40s」，但回合横幅仍挂着

> 模型输出尚未结束，正在继续执行。

那句话里的「**正在继续执行**」已经是假的 —— 执行早已结束。

## 2. 根因：白名单与后端零交集

### 后端实际发的 notice（共 3 处 yield，去重 **2 条**）

| 位置 | 文案 | 触发条件 | 语义 |
|---|---|---|---|
| `agent.py:4914` | 模型单次输出已满，正在接续完整回答。 | `finish_reason == "length"` 且续写额度未用尽 | **事实**：答案真被单次输出上限截断过 |
| `agent.py:5816` | 模型输出尚未结束，正在继续执行。 | 既没 `Action:` 也没 `Final Answer:` → 纠偏重试 | **过程**：格式没写完，重试中 |

### 前端白名单（`useChatStream.ts:114`）

```ts
const transient = /^(已进入模型处理|模型仍在处理|正在准备本轮上下文|正在等待模型输出)/.test(ev.text)
if (!transient && !turn.notices.includes(ev.text)) turn.notices.push(ev.text)
```

**这 4 条后端一条都不发**（`c19aacf` 为兼容老服务端加的，那些文案早已不存在）。

实测对照：

```
白名单 4 条  ->  全部是死条目（后端从不发）
后端 2 条    ->  一条都不被过滤（都留在历史里）
```

**交集为零。** 截图那句正是第 2 条。

## 3. 为什么不该「往白名单加个词」

1. **只修一半** —— 第 1 条（`模型单次输出已满`）同样会在结束后留着，
   而它**该留**：答案真被截断过，这是用户需要知道的事实。
2. **逐条列举已经失效过一次** —— 那 4 条死条目就是上次这么加的结果。
   后端下次新增一条，前端又漏一条。
3. **根因是 `notices` 一旦 push 就没人清** ——
   实测 `useChatStream.ts` 里**没有任何一处** `notices = []` / `length = 0`，
   `final` / `done` 都不清。所以任何运行期提示都会在任务结束后变成过期陈述。
   只改过滤规则，下一条新文案照样漏。

## 4. 建议改法

把判据从「**这句文案是不是过时**」换成「**这条 notice 是不是运行期进度**」：

1. 后端给 notice 事件加**结构化标记**（例如 `transient: true`），
   语义由**发它的后端**决定，而不是由前端比对文案猜。
2. 前端按标记处理：`transient` 的进运行指示器（不进历史），
   其余（例如「输出被截断」）留在通知里。
3. 回合结束时清掉 `transient` 类。

这样后端以后新增任何运行期提示，前端都不需要改。

⚠ **别把「那 4 条死条目」留着当兼容性保险** —— 当前后端不会发它们，
留着只会让人误以为过滤在生效。

## 5. 边界：什么该留、什么该走

| 文案 | 该不该进历史 | 为什么 |
|---|---|---|
| 模型输出尚未结束，正在继续执行。 | **不该** | 纯过程。结束时它变成假陈述 |
| 模型单次输出已满，正在接续完整回答。 | **该留**（或转成最终提示的一部分） | 事实：答案确实被截断过 |

**别把两条一起过滤掉** —— 那会把「答案被截断」这个事实一起吞掉。

## 6. 本文的断言怎么验的

```python
# 后端实际发的 notice
re.findall(r'"type":\s*"notice",\s*"text":\s*"([^"]+)"', agent.py)

# 前端白名单逐条与后端对照
re.search(r"const transient = /(.+?)/\.test", use_chat_stream_src)

# notices 有没有清理逻辑（断言「一处都没有」）
re.findall(r"notices\s*=\s*\[\]|notices\.length\s*=\s*0|notices\.splice", src)  # -> []
```

## 7. 测试现状：没有锁

- `tests/` 里**没有任何测试断言 notice 的过滤行为**。
  `test_context_usage.py:206-209` 只测「压缩提示出现过」，不测前端过滤。
- ⚠ `transient` 这个词在 `tests/test_tool_failure.py` 里是**另一个意思**
  （工具失败分类：`timeout` 属 transient），与 notice 无关 ——
  搜到它别以为有关联。

**所以这处改完需要补一条锁**：断言「后端发 `transient: true` 的 notice
不会出现在 `turn.notices` 里，且不发该标记的会留」。
