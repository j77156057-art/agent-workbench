# 已知缺陷：子代理的写授权由角色提示词决定，与用户请求无关

> 实测确证（HEAD `72479b0`）。**未修** —— 修法是方向性决策，需要先定方案。

## 现象

`agent.py:5669` 子代理跑的是 `child.run(question)`，而 `question = spec["hint"]`
（5614 行）—— **那是角色提示词，不是用户的请求**。

子代理的写意图护栏判的因此是那串提示词。判定结果完全由硬编码文本决定：

| 角色 | 判定 | 因为提示词里 |
|---|---|---|
| 游戏设计专员 | **granted** | 「可以**创建**设计文档」 |
| 美术专员 | **granted** | 「**创建**或整理最小可用的游戏素材」 |
| 音频专员 | **granted** | 「只在授权范围内**创建**配置」 |
| 检索专员 | denied | 「不要改任何文件」 |
| **实现专员** | **denied** | 「在授权范围内**改**代码」|
| 评审专员 | denied | 「禁止修改任何文件」 |

**两个方向同时坏**：

- **实现专员永远不能改代码** —— 而它的职责就是改代码
- **游戏/美术/音频专员无条件拿到写权限** —— 与用户说了什么完全无关

## 端到端证实

```
用户实际请求: '帮我改一下 player.gd 的数值配置'
  -> 主 agent 判定 granted

子代理护栏实际判的: '你是【实现专员】：在授权范围内改代码，最后说明改了哪些文件与为什么。'
  -> denied

真跑一个实现专员子代理：
  apply_edit(path: player.gd) [已拦截：未授权写操作]
  [安全拦截] apply_edit 未执行：用户没有要求创建或修改文件。
```

拦截消息是 **「用户没有要求创建或修改文件」**，而用户**明确要求了**。

这属于代码注释里自己警告过的那一族：**把不知道的说成知道了**。护栏对我们的无知
使用了断言用户意图的措辞 —— 而实际上用户的意图就在父 agent 手里，只是没传下来。

## 对 `449ebf9`（租约接线）的影响

**那一笔对子代理零作用。** 设计时假设「子 agent 继承父的租约，所以不需要自己的
授权」—— 但子 agent 的护栏**根本不查租约**，它查的是提示词。

租约继承是真的（`capability_lease=self.capability_lease`，5430 行），但**没人问它**。

## 修法方向（需先定）

### A. 把用户的请求传进子代理，让护栏判**它**

子代理已有的 `context` 参数（上游结论注入）可以带上原请求。改动小，但治标：
提示词里若有「不要改」之类字样仍会被判否。

### B. 子代理的写护栏改查**继承来的租约**，不查提示词

与调研结论一致：**权威来自结构，不来自散文**。子代理不该从自然语言里猜权限。
父 agent 已经用 `tool_allowlist` 结构性限制了子代理能用什么工具
（`_run_child` 的 `tool_allowlist=allowed or list(spec["tools"])`），
写许可本可以走同一条路。

### C. 给角色**声明**能力，而不是让护栏读它的提示词

与 `ToolSpec.capability` 同一个思路：角色的写权限应该是声明式的
（`{"write": true/false}`），不是从「可以创建」这四个字里推断出来的。

**C 最干净，且与已核实的三家 harness 做法一致**（opencode 查授权表、
Pi 推给容器、Hermes 查工具开关 —— 没有一家是从散文里推断权限的）。

**但 C 的改动面最大**：要动角色定义、`_run_child`、以及三处只看 `status != "ok"`
的消费点（5833 / 5860 / 5927）。

## 顺带：子代理的失败无法上浮

`agent.py:5794` 的返回只有 `status: "ok" | "failed"`（5791 由反思决定），
**没有任何字段能让父 agent 区分「子代理失败了」和「子代理被授权问题卡住了」**。

所以即使修了上面的方向问题，子代理一旦再次被卡，父 agent 也只会看到
「researcher 失败」，不知道该去问用户什么。需要给返回加字段，并让三处消费点
把它当作「需要用户确认」而不是失败。

## 修这一族时必须守住的

1. **不能让子代理比父 agent 权限更大** —— 现在那三个游戏角色就是反例
2. **拦截措辞不能说「用户没有要求」** —— 除非我们真的确认过；子代理层面我们
   **没有**用户的原始请求，所以正确说法是「拿不准」
3. 修完必须验证**实现专员能改代码**且**检索专员仍然不能** —— 这两个是同一族的
