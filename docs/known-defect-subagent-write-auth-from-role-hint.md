# 子代理的写授权：已改为结构化（原「由角色提示词决定」那条已修）

> 修复提交：`fa81aa3`。本文档原记录的是**已修缺陷**，现在补上修法与验证。
> 原始现象保留在第 1 节，便于对照。

## 1. 原缺陷（已修）

`agent.py:5669` 子代理跑 `child.run(question)`，而 `question = spec["hint"]`
（5614 行）—— 那是**角色提示词**，不是用户的请求。护栏判的因此是那串硬编码文本：

| 角色 | 提示词里的字 | 改前判定 |
|---|---|---|
| coder | 「在授权范围内**改**代码」 | **denied** |
| designer | 「可以**创建**设计文档」 | granted |
| artist | 「**创建**或整理素材」 | granted |
| audio | 「在授权范围内**创建**配置」 | granted |
| researcher | 「不要改任何文件」 | denied |

**11 个角色里 10 个碰巧对，唯一错的就是 coder** —— 职责就是改代码的角色永远被拦；
而 designer/artist/audio 的写权限与用户说了什么**完全无关**。

端到端曾实测：用户「帮我改一下 player.gd 的数值配置」-> 主 agent 判 granted；
子代理判提示词 -> denied；拦截消息是**「用户没有要求创建或修改文件」**，
而用户明确要求了 —— 这属于代码注释里自己警告过的「把不知道的说成知道了」。

## 2. 修法：权威来自两处结构，二者都要成立

1. **`tool_allowlist`** —— `agent.py:4571` 已拦不在名单里的工具；且
   `_READ_ONLY_ROLES` 会按 `ToolSpec` 把写工具从只读角色的请求里滤掉
   —— **这个机制本来就有**，那段代码的注释里已写明「权威分类只有一份，
   不要手抄工具名清单」。本笔只是让护栏**别再去和它对着干**。
2. **父 agent 的授权租约** —— `_run_child` 已继承（5430 行）。

与 opencode 查授权表、Hermes 查工具开关同一个思路：**权威来自结构，不来自散文。**

抽出两个方法，让判据可被直接调用与变异：

- `Agent._intent_for_top_turn(question, action_name)` —— 顶层读用户原话 + 铸造/消费租约
- `Agent._intent_for_delegated(action_name)` —— 委派层只认租约与工具集

## 3. 一个必须显式要求的条件

`_lease_blocked` 在**没有租约时返回不拦**（`if not lease or spec is None:
return False, ""`）。所以「租约不拦就放行」是错的 —— 那等于**父 agent 从未
授权也能写**。第一版就漏了这一句，由探针当场抓出（无租约时 `apply_edit` 仍
`blocked=False`）。

现在 `_intent_for_delegated` 第一句就是 `if not self.capability_lease:
return DENIED`。

## 4. 仍未解决：子代理的失败无法上浮

`agent.py:5794` 的返回只有 `status: "ok" | "failed"`（5791 由反思决定），
**没有任何字段能让父 agent 区分「子代理失败了」和「子代理被授权问题卡住了」**。

三处消费点（5833 / 5860 / 5927）全都只看 `status != "ok"`，所以子代理一旦被卡，
父 agent 只会看到「researcher 失败」，**不知道该去问用户什么**。

修它要给返回加字段，并让三处消费点把它当作「需要用户确认」而非失败。字段
必须**必填**（缺失按失败处理），否则老路径会静默走偏。

## 5. 已知代价：租约让审查类问题在 TTL 内不再被拦

父 agent 说过「改吧」之后，接下来一轮即使问的是「分析一下架构」，写操作也放行 ——
这是租约存在的意义（把批准物化成事实，而不是每轮重猜）。方向是**放宽**，
所以 TTL 被夹在默认 300s / 上限 900s。

守卫 `test_the_lease_does_let_a_later_review_turn_write_and_that_is_intended`
把这条行为**正面钉住**，避免将来有人误当成 bug 改掉。

## 6. 验证

`tests/test_subagent_write_auth.py` 11 条，**正反两面都测**：

| 守卫 | 钉住什么 |

| coder 有租约能写 | 正向：职责就是改代码的角色必须能写 |
| researcher 即使有租约也拿不到写工具 | 反向：只读角色 |

变异 **4/4**。组合回归 402 passed / 7 skipped / 17 subtests（含 29 道 dev_eval 门禁题）。

## 7. 本笔暴露的三种「自己的错」（都写在这里了）

1. **第一版引入 fail-open** —— 见第 3 节。
2. **测试在复刻生产逻辑** —— 第一版守卫写的是 `bool(lease) and not blocked`，
   一个**副本**。变异生产代码时它毫无反应：4 条变异只咬住 1 条，**没咬住的
   三条恰好全是安全方向最关键的**。抽出方法后守卫直接调它，立刻咬住。
3. **变异方向反了** —— 把「要求租约存在」替成「不要求」，那是修复方向。
   变异必须从**正确版**替到**错误版**。

补完 2、3 后仍有一条没咬住：它改的是**调用点**（`if self.depth > 0` 变成
`... and _write_intent(question) == "denied"`），而直接调方法的守卫**看不见
调用点的变化**。于是补了走主循环的门级测试 —— 直接调方法测不到「走哪条分支」。

4. **一条测试的 `def` 行被 edit 掉**，函数体并进了相邻测试。`10 passed` 却
   没多出一条，才察觉。补回后 11 条。

**判据：测的必须是被测物本身，不能是它的副本，也不能是它的调用点。**
