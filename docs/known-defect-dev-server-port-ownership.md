# 5173 上「别人的服务」没有归属校验：注释声称有，实际不存在

> 状态：**归属判据与静默替换已修**（`dev_server.owns_port()` + `resolve_live_url()`），
> 文案里的写死端口已去掉。发现于 2026-10-08 排查 DocMind 前端 dev server 的过程中。
> 归属：跨层（`agent_runtime/dev_server.py` + `visual_acceptance.py` + 前端 vite 配置），
> 需后端侧定夺，前端单方面改端口只会把契约撕开（见第 5 节）。
> **已做**见第 8 节；**仍未做**见第 9 节。

## 1. 一句话

`agent_runtime/dev_server.py:36` 的注释写着：

> 更糟的是那个地址上可能正站着**别人的服务**（见 `owns_port`）。

但 `owns_port` **全仓只出现在这一行注释里** —— 从未定义、从未被调用。
`dev_server.py` 的公开函数只有 `free_port` / `loopback_url` / `parse_port_hint` /
`port_taken` / `probe` / `start` / `stop` / `render`。其中 `port_taken(port)` 只回答
「这个端口有没有人在听」，不回答「在听的那个是不是我起的」。

注释把风险点名了，又用一个不存在的函数让读者以为它已被处理。

## 2. 本机实际存在的场景（不是假设）

```
TCP  [::1]:5173      LISTENING  24352   node  ← D:\study\tools\agent\new agent
                                                 \.worktrees\qoder\frontend 的 vite
                                                 （启动于 2026-10-08 00:08:36）
TCP  127.0.0.1:5173  LISTENING  (DocMind 自己的 vite)
```

两个 vite **同号、不同地址族**，因此互不冲突、同时存活。而
`netstat -ano -P TCPv4` 看不到 IPv6 那条监听 —— 排查者会误判成「那个进程没了」。
本次排查中我就误判过一次，是查 `CommandLine` 才发现那根本是另一个项目的服务。

## 3. 后果链

> 以下是**发现时的状态**。第 1 环已断（8.3），第 2 环加了早失败（8.2）。

1. `agent.py` 的 `preview_project` 文档，叫模型传字面量
   `url: http://127.0.0.1:5173/`（并注明「只允许回环地址」）。
2. `visual_acceptance.py:788` 用 `loopback_url(url)` 校验 —— 但它只判「是不是回环」，
   不判「是不是本会话起的那个服务」。
3. `visual_acceptance.py:801`：给了 `url` 就**不再起自己的静态服务**，直接截那个地址。
4. DocMind 的 vite 一旦因撞端口漂到 5174（`dev_server.py:34` 自己描述的行为），
   而 5173 上站着别的项目的服务 —— **验收截图拍到的是别人的画面，并且报告成功。**

这是「把不知道的说成知道了」那一族里最糟的形状：证据看起来完全有效，
画面是真的、浏览器是真的、没有报错，只是**不是本项目**。

## 4. 已顺带修掉的另一半

`869773c`：vite 之前用默认配置只绑 `[::1]`，而上面第 3 节的契约字面量是
`127.0.0.1` —— 那条路不是偶发失败，是**必断**。改绑 IPv4 loopback 后，
`http://127.0.0.1:5173/` 与 `localhost` 都能通，且不再把 dev server 暴露到局域网
（`host: true` 会绑 `0.0.0.0`，实测 `http://10.215.20.161:5173` 可访问）。

旁证：`dev_server.py:30` 的 `_PORT_LINE` 与 `tests/test_dev_server.py:61` 用的字面量
正是 `http://127.0.0.1:5173/` —— 改完之后真实输出才符合测试早就在假设的形态。

**归属校验仍然缺失**，本篇记的就是这一半。

## 5. 为什么不能单方面改端口

> ⚠ **本节的部分引用已在第 8.3 节失效** —— 那些教模型的字面量已被去掉。
> 下表的**漂移契约部分**（`dev_server.py` 的行为描述、测试、变异电池）**仍然有效**。

5173 不是前端自己的常量，是被跨层字面引用的契约：

| 位置 | 引用形态 | 现状 |
|---|---|---|
| `agent.py` `preview_project` / `dev_page_action` 说明 | 工具文档里的 `url:` 示例 | **已改**为 `<实际端口>`（8.3） |
| `tools.py` 4 处 `preview_project` / `dev_page_action` 参数说明与示例 | 工具参数说明与示例 | **已改**为 `<实际端口>`（8.3） |
| `agent_runtime/dev_server.py:34 / 73 / 85` | 漂移行为描述与报错文案 | **仍然有效** |
| `tests/test_dev_server.py:61-73` | 断言漂移时认到 5174 | **仍然有效**（守卫 8.4 钉住） |
| `tests/mutation/battery_dev_server.py:65,120` | 把 fallback `5173` 钉成变异守卫 | **仍然有效** |

## 6. 建议方向（留给后端定）

最小且不动契约的做法：把 `owns_port` 真的实现出来，并在 `preview_project` 收到
`url` 时要求它匹配**本会话 `dev_serve` 记录的实际端口**，不匹配就拒绝并说明
「5173 上有别的服务，本会话的服务在 5174」。也就是让第 2 节那条 `port_taken()`
升级为能回答归属问题，而不是新增端口约定。

## 8. 已修（2026-10-08，后端侧定夺）

第 6 节的建议方向被采纳，但**落法与原文不同** —— 原文建议「不匹配就拒绝」，
而实际做出来的是**不给标记就不下结论**。原因见下。

### 8.1 `dev_server.owns_port()`：把注释里那个不存在的函数实现出来

`owns_port(port, markers=...)` 判「这个端口上是不是**我要的那个**服务」：
页面上有没有调用方给的项目指纹。

关键设计：**不给 `markers` 时不做归属判断**，返回「无法判归属」而不是猜。
宁可让调用方多传一个标记，也不要静默把别人的服务认成自己的 ——
那是**假绿灯**，比报错更难发现。

`probe()` **保持只判「通不通」**，没有被改成判归属（有意如此：它有多处消费点
按「通不通」用，改它会动既有契约）。归属判断是**新增能力**，走新函数。

`dev_server.py:36` 那条注释引用的 `owns_port` 从此不再是失效引用。

### 8.2 `resolve_live_url()`：**不静默换端口**

**我第一版写错了，值得单独记。** 第一版是「给定地址不通就按候选端口逐个探，
**取第一个能应答的**」。

**那是把同一个假绿灯换了个入口。** 能应答不代表那上面跑的是本项目 ——
静默选一个候选并截图报成功，比「打错端口超时」更难发现，因为它**看起来是成功的**。

正确行为：`capture_project_preview` 只在**给定地址自己应答**时沿用它；
不通就**早失败**，并把在应答的候选端口**列出来让人认领**，同时写明
「能应答不代表那上面跑的是本项目，不要默认就是它」。

不替它选，是因为**替它选就必须做归属判断**，而归属判断需要项目指纹 ——
`preview_project` 手上没有。猜就是回到假绿灯。

结果里带 `url_resolution` 字段，让「打了哪个地址、为什么」在证据里可查。

### 8.3 文案：不再教模型写死端口

第 3 节后果链的第 1 环被切断。`agent.py` 的 `preview_project` / `dev_page_action`
说明，以及 `tools.py` 里 **4 处** `preview_project` / `dev_page_action` 参数说明与示例，
全部从 `url: http://127.0.0.1:5173/` 改成 `url: http://127.0.0.1:<实际端口>/`，
并指向 **`dev_serve` 返回的那个地址** —— `dev_serve.render()` 本来就明说
「接着用 `preview_project` 的 `url:` 打这个地址」，即真地址一直在返回里，
只是文案在把模型往字面量上引。

**只删字面量是不够的**（那等于让模型自己猜端口，比写死更糟），
所以守卫里有一条**正向守卫**钉住「指了路」这个事实。

### 8.4 不许被「统一文案」推翻

`tests/test_preview_port_prompt.py` 扫 `agent.py` + `tools.py`，
任何 `http://127.0.0.1:5173|5174/` 字面量都会让它红。这条很容易被
「顺手把示例补全」推翻 —— 而推翻后 `parse_port_hint` 与漂移用例虽然仍绿，
**失败会静默发生**：模型照着死地址访问，报告却说「没认到端口」。

守卫同时钉住漂移契约本身（`parse_port_hint` 仍取最后一个匹配），
免得有人以为这一族可以一起动。

### 8.5 为什么否决 `strictPort: true`

第 5 节已经说了它会让 vite 退出而不漂移。补一条更硬的：
它不只是「让 `parse_port_hint` 认不到」，而是让那个函数的**存在意义消失** ——
那函数存在的唯一理由就是「从一堆可能含死地址的日志行里认活的」。
vite 不漂移了，日志只有一行，「认端口 + `owns_port` 验归属」整套机制连同它的
变异守卫全都失去对象。

而 `869773c`（`host: '127.0.0.1'`）**保留**：它修的是真断掉的东西（第 4 节），
且它与后端契约**一致** —— 让 vite 的实际输出符合测试早就在假设的形态。
`host` 是对齐，`strictPort` 才是撕开。

## 9. 仍未做

> **2026-10-08 补充**：`owns_port` **接不了生产**，原因不是忘了接线，
> 而是**页面里没有能区分项目的指纹**。完整核实与修法见
> **`docs/known-defect-port-ownership-has-no-fingerprint.md`**。
> 简版：三个候选指纹（`<title>` / 项目名注入 / dev URL）实测**全部不可用** ——
> 三个入口的 title 都以 `DocMind` 开头，而 worktree 跑的是**同一份代码**。
> 真正的修法是**前端在 dev 时注入项目身份**
> （约定见 `docs/frontend-task-project-identity.md`，属前端域）。

* ~~**`preview_project` 不知道本会话 `dev_serve` 起的服务在哪个端口。**~~
  这条已不是主要障碍：`dev_server` 没有「按 job_id 查状态」、
  `process_runner` 也没有「列出活跃 job」，但**更重要的是归属判据本身用不了**。
  且即便传了 `job_id:`，撞端口的 worktree vite 也不是经 `dev_serve` 起的。
* **`owns_port` 还没有生产调用点** —— 已用守卫
  `test_it_still_has_no_production_caller` 把这个状态钉住，
  一旦有人接线它会红并提醒同步更新文档。
* **IPv6 那条监听仍然看不见**（第 2 节）。`netstat -ano -P TCPv4` 看不到 `[::1]`，
  排查者会误判成「那个进程没了」。这条属于运维排查体验，不在本次范围。

### 两个洞，不是一个

第 8.2 节挡的是「**地址不通时换一个**」；
而「**地址通、但不是我的项目**」这个洞要等前端注入身份后才堵得上。

**只有前者被堵住了。** 别把 8.2 当成归属校验已完成。
