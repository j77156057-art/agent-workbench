# 「补」这个动词不在授权词表里 —— 而它是最自然的一类编码动词
> ⚠ **本篇里的「本轮」指 2026-10-08 那一轮**（下午，不是晚上 ——
> 我原先写「今晚」是沿用了旧上下文的措辞、没核实时间，已全部改掉）。
> 相对时间词在交接文档里等于信息丢失。

> 立档：**2026-10-08**，来自 §6 端到端验证（`tools/e2e_guard_effect.py` 真跑）。
> **这是本仓库唯一一个由真模型端到端发现、而单元测试与语料库都没记录到的判定缺口。**

## 1. 现象

用户给的任务**明确到不可能误解**，却被判 `denied`：

```
denied   请给 a.py 里的 add 函数补一个 docstring
denied   给 a.py 补 docstring
granted  给 a.py 加 docstring          ← 同一个意图，只换了动词
granted  请修改 a.py
granted  把 a.py 的 add 函数改成正确的加法
```

**「补」不在授权动词表里。** 而「补 docstring / 补注释 / 补测试 /
补充文档」是编程助手里**用户最自然的一类动词**。

## 2. 端到端现场（真模型 `qwen3.6:35b-a3b`）

§6 题型第1 轮原文就是这么写的，于是：

| 轮 | 用户说 | 判定 | 实验组结果 |
|---|---|---|---|
| 1 | 「请给 a.py 里的 add 函数补一个 docstring」 | **denied** | **未动文件**（模型只输出问题分析） |
| 2 | 「这个改起来要几步？」 | denied | 未动 |
| 3 | 「改吧」 | denied | 未动 |

而模型在第 3 轮的原话：

> 「由于本轮未获得明确的『修改』授权，我无法直接执行写操作。以下是具体的修改建议，
> 您可以自行在编辑器中操作：」

**护栏在正常工作，模型也准确理解了护栏状态** —— 但它把一个明确的编码任务
判成了「未授权」。

## 3. 为什么这不是 `docs/write-intent-corpus.md` B 节那个已知缺口

B 节记的是**裸动词**（「改」「修」「写」单字无宾语）→ `6069386` 把它锁成
`denied` 并留了守卫 `test_a_sentence_with_only_a_bare_verb_is_not_granted`。
**那是有意的保守设计**（裸动词确实模糊）。

而本条的形状**相反**：

| | B 节（已知、有意） | 本条（未记录） |
|---|---|---|
| 句子 | 「改吧」—— **无宾语** | 「请给 a.py 里的 add 函数补一个 docstring」—— **有明确文件、有明确函数、有明确动作** |
| 判定 | denied（**有意**） | denied（**漏**） |
| 有守卫记录 | ✅ `6069386` | ❌ **零记录** |

**语料库文档里搜不到任何一处提到「补」+ `docstring` 的组合。**

## 4. 真实后果：不是「误拦一轮」，是**整个任务做不下去**

§6 真跑里暴露了一个**链式效应**：

1. 第 1 轮（明确授权的任务）判 `denied` → **没有铸造租约**
2. 后续轮次全部 `denied`（租约不存在，无从让位）
3. **用户无论追加多少句都解不开** —— 他必须猜到该说「请修改 a.py」
   而不是「补 docstring」

而 §1 那批词表改动的**单测全部用「实测 granted 的样本」**（如「改一下端口」），
所以它们绿。而真实用户**不会**照着词表说话。

> **这就是 §6 存在的理由：「单元绿 ≠ 端到端绿」。**
> 单元测试验证的是「词表里有的词判得对」，
> 端到端验证的是「用户真的会那么说」。

## 5. ⚠ **不要靠加词解决**

本条的**正确处置不是把「补」加进词表**，理由有三：

1. **本轮已经实测到同样的形状不止一次**：`裸动词改`（已记 B 节）、
   `补`（本条）。而真实语言里的编码动词远多于任何词表 ——
   补/加/续/完善/收敛/规整/清理/整理/抹平/收尾/对齐…
   **加词是打地鼠。**
2. **Pi 明确否定了这一整类**：`watching the transcript is not a security boundary`，
   而我们自己的 `write-intent-corpus.md` 已经独立得出同一结论
   （「别再往写意图词表里加词」）。
3. **真正的缺口不是词表，是「用户怎么表达授权」这件事没有被正面解决**。
   用户说了「补 docstring」，那是**事实**；把它当字符串猜是本末倒置。

## 6. 该走哪条路（**都不在本轮做**）

| 方向 | 说明 | 状态 |
|---|---|---|
| **结构化授权** | 授权来自 UI（一个明确的「允许修改」按钮）而不是文本 —— **这才是「事实」形态** | 已有基础：`ToolSpec.capability` / `_lease_blocked()` 是结构化的那一半 |
| **interrupt-and-redirect** | 用户能在模型干活时改向；把「补 docstring」这类**明确的实施要求**与**授权**分开 | 见 `harness-research-verified.md` §2.10，缺口已核实 |
| 租约跨轮 | `_intent_for_top_turn` 的租约让位机制**已存在**，但要有一轮 granted 才能铸造 | 链条的起点就是本条 |

⚠ **注意链条的顺序**：只要第 1 轮判 denied，后面全部无从谈起。
所以**第 1 轮的判定质量是关键** —— 而它现在靠一个不完整的词表。

## 7. 探针与复算

* `tools/e2e_guard_effect.py` —— §6 端到端（本条的**来源**）
* 复算（**不需要模型，秒级**）：
  ```python
  from agent import _write_intent, _WRITE_INTENT_GRANTED
  _write_intent("请给 a.py 里的 add 函数补一个 docstring") == _WRITE_INTENT_GRANTED  # False
  _write_intent("给 a.py 加 docstring") == _WRITE_INTENT_GRANTED                   # True
  ```
  这两行就是判据 —— **一个动词的差别，两个相反的结果**。

## 8. 与 §6 判定的关系（诚实交代）

§6 那次跑的**判定是「说明不了任何事」**（两组在第 2 轮都没改文件），
因为**我把判据轮次选错了**（第 2 轮时对照组的活已在第 1 轮干完）。

但**第 1 轮其实有信号**：对照组改动了 `a.py`，实验组没有。
所以「护栏确实拦住了」这一点在第 1 轮成立 —— 拦住的**理由**却是本条那个缺陷。
